## 4. Normalized schema, provenance, and verdict mapping

Each edge response contains:

```json
{
  "grade_id": "sha256(image bytes + vendor + mode + timestamp)",
  "image_sha256": "sha256(image bytes)",
  "vendor": "mock|g1",
  "mode": "sdxl|flux_schnell|real",
  "ai_probability": 0.0,
  "deepfake_probability": 0.0,
  "verdict": "CLEAR|NEAR|BORDER|FAIL",
  "top_source": "family-or-null",
  "sources": {},
  "swap_index": 0.0,
  "retention_index": 0.0,
  "raw": {},
  "mock": true,
  "cache_hit": false,
  "provider_calls": 0,
  "requested_mode": "real",
  "session_usage": { "vendor_calls": 0, "cap": 40 }
}
```

Verdicts use the frozen inclusive boundaries:

- `0.00 <= p <= 0.10`: CLEAR. Exactly `0.10` is CLEAR.
- `0.10 < p <= 0.15`: NEAR. Exactly `0.15` is NEAR.
- `0.15 < p <= 0.30`: BORDER. Exactly `0.30` is BORDER and is QA-flagged.
- `0.30 < p <= 1.00`: FAIL.

Provider probabilities in either `0..1` or `0..100` are converted to `0..1`; non-finite, negative, or above-100 values are rejected and never cached. Source keys are trimmed/lower-cased and values are normalized to `0..1`. An empty source map yields `top_source: null`. For a remint grade, its source mass is split by membership in the OG top three families: absent mass becomes `swap_index`, present mass becomes `retention_index`; they sum to 1 when remint source mass is non-zero. OG grades have both indices set to zero.

The ledger captures requested settings separately from the executed worker report. It stores the full received report plus a SHA-256 digest and explicit extracts for `settings`, `attempts`, `finish_adaptive`, `detector_gate`, `rating_88`, and Quality Finish `qc`. This preserves executed-not-requested provenance. Vendor raw response keys matching API-key/token/authorization/secret/endpoint patterns are redacted server-side before cache or export.

The selected-image **Run detection only** event has a separate schema and storage key. It calls `gradeImage(file, "og")` only, passes no settings code, and records `settings_code: null`, `worker_job_id: null`, `remint_dispatched: false`, and `remint_credits_spent: 0`. It cannot be exported as, imported into, or rendered as an OG/remint pair.

## 5. Cache and budget counters

- Cache key: `(image_sha256, vendor, mode)`, enforced by the draft table primary key.
- Cache reads occur before provider reservation/call. A cache hit returns `provider_calls: 0`; pair-dependent swap/retention is recomputed against the supplied OG grade rather than stored in the global base grade.
- Failed provider attempts and failed normalizations are never cached. A mode gets at most one retry; if it still fails and differs from the configured default, the default mode is used and `vendor_error` records the fallback without exposing endpoint or credentials.
- `grade_sessions` counts actual real-vendor attempts, including the permitted retry/fallback attempts. `reserve_grade_call` increments atomically only while below the server-owned cap.
- The server default is 40 calls per browser session UUID. `GRADE_SESSION_CAP` is the owner override and is clamped to `1..10000`. The browser cannot raise it.
- `/relab` displays returned grades, cache hits, and authoritative session vendor calls/cap. MOCK responses make zero vendor calls. The migration must be owner-approved/applied before real grading; real G1 operation refuses a missing cache or budget store.
